A khaos binding is an adapter around `khaos_core`. It translates language values into Rust values, calls the core, and translates the result back. It does not implement extraction, pool mixing, or generation itself.

## Dependency direction

```text
application
    ↓
language package
    ↓
native adapter
    ↓
khaos_core
```

Dependencies point toward the Rust core. The Rust core must never depend on a language binding.

## Stable conceptual contract

Every binding should expose the same three concepts even when naming follows the target language:

| Concept  | Input                                     | Output              | Purpose                                                    |
| -------- | ----------------------------------------- | ------------------- | ---------------------------------------------------------- |
| Inspect  | Raw sample bytes                          | Entropy report      | Observe sample shape without generating output             |
| Generate | Raw sample bytes and output length        | Random bytes        | Use operating-system seeding and one physical contribution |
| Replay   | Seed, raw sample bytes, and output length | Deterministic bytes | Reproduce tests and demonstrations                         |

The current TypeScript names are `inspectEntropy`, `generateBytes`, and `replayBytes`.

## Binding responsibilities

A native adapter should:

1. Accept the target language’s byte-buffer type.
2. Reject invalid lengths before allocation.
3. Convert the buffer to a Rust byte slice.
4. Call a public `khaos_core` function.
5. Convert `EntropyReport` into a native object or record.
6. Convert `EntropyError` into an idiomatic target-language error.
7. Return owned output bytes without text encoding.

A native adapter should not:

- Reimplement Von Neumann unbiasing.
- Hash samples independently.
- Maintain a different generation counter.
- Replace OS randomness with a language runtime PRNG.
- Convert generated bytes to hexadecimal by default.
- Claim entropy estimates that the Rust core does not calculate.
- swallow extraction or system-randomness failures.

## Suggested repository layout

Give every binding a dedicated crate and every high-level package a dedicated package directory.

```text
crates/
├── khaos_core/
├── khaos_napi/
├── khaos_python/
├── khaos_wasm/
└── khaos_ffi/
packages/
├── typescript/
├── python/
└── wasm/
```

Use only the directories that correspond to real bindings. A language may need one native crate, one high-level package, or both.

## Choose the boundary

| Target                                   | Typical Rust bridge | Package layer             |
| ---------------------------------------- | ------------------- | ------------------------- |
| Node.js                                  | NAPI-rs             | TypeScript                |
| Python                                   | PyO3 and maturin    | Python package            |
| Browser or edge WASM                     | wasm-bindgen        | TypeScript                |
| C, Swift, Kotlin, or other FFI consumers | `extern "C"` ABI    | Language-specific wrapper |

Choose an established bridge for the target ecosystem. Do not expose Rust’s internal memory layout as a public protocol.

## Keep names idiomatic

The conceptual API should remain consistent, but public names should follow the target language.

| Concept      | TypeScript       | Rust                     | Example Python    |
| ------------ | ---------------- | ------------------------ | ----------------- |
| Inspect      | `inspectEntropy` | `analyze`                | `inspect_entropy` |
| Generate     | `generateBytes`  | `generate`               | `generate_bytes`  |
| Replay       | `replayBytes`    | `generate_deterministic` | `replay_bytes`    |
| Report field | `inputBytes`     | `input_bytes`            | `input_bytes`     |

Document the mapping so users can move between language guides without guessing.

## Preserve byte semantics

Bindings should accept and return bytes, not strings.

- TypeScript uses `Uint8Array`.
- Node.js may pass `Buffer` because it extends `Uint8Array`.
- Python should use `bytes`, `bytearray`, or a documented buffer protocol.
- WASM should use `Uint8Array`.
- C should use a pointer and explicit length.

Text, hexadecimal, Base64, and Base64url are application encodings. They belong outside the cryptographic core and outside the default binding API.

## Map reports without changing meaning

Every binding should preserve the three current report fields:

```typescript
type EntropyReport = {
  inputBytes: number;
  unbiasedBits: number;
  onesRatio: number;
};
```

`onesRatio` is an observation of raw bit distribution. It is not an entropy estimate, quality score, or security grade. Bindings must not rename it to imply otherwise.

## Map errors explicitly

Bindings should preserve the distinction between core failures.

| Rust error                    | Binding meaning                                |
| ----------------------------- | ---------------------------------------------- |
| `EmptyInput`                  | The caller supplied no sample bytes            |
| `BiasedInput`                 | No pair survived Von Neumann unbiasing         |
| `OutputTooLarge`              | The caller requested more than 1,048,576 bytes |
| `SystemRandomnessUnavailable` | The operating system could not seed the pool   |

Prefer typed or inspectable errors when the target ecosystem supports them. Error text may improve over time; application behavior should depend on a stable code or variant rather than matching full messages.

## Design a stateful pool carefully

Future bindings may expose `EntropyPool`, but a long-lived native object adds lifecycle decisions that one-shot functions avoid.

Define these rules before publishing a stateful API:

- Whether one instance can be called concurrently.
- Whether calls are serialized by the binding or rejected.
- How the native object is disposed.
- Whether the language runtime may clone or move the handle.
- What happens after process fork.
- Whether generated output crosses thread boundaries.
- How pool state is protected from debug serialization.
- Whether a failed mix leaves the previous state unchanged.

Start with one-shot functions when the target bridge cannot express ownership safely.

## Test every binding at three levels

### Core contract tests

Run the shared Rust tests to verify cryptographic behavior.

```bash
cargo test -p khaos_core
```

### Native adapter tests

Verify conversion and error behavior in the adapter crate.

```bash
cargo test -p khaos_napi
```

Replace the package name for another adapter.

### Language package tests

Call the package exactly as an application would.

```typescript
import assert from "node:assert/strict";
import test from "node:test";
import { inspectEntropy, replayBytes } from "@khaos/typescript";

test("reports the original sample length", () => {
  const report = inspectEntropy(Uint8Array.from([105, 150, 90]));
  assert.equal(report.inputBytes, 3);
});

test("replays equal inputs deterministically", () => {
  const seed = new TextEncoder().encode("binding-contract");
  const sample = Uint8Array.from([105, 150, 90]);
  const first = replayBytes(seed, sample, 32);
  const second = replayBytes(seed, sample, 32);
  assert.deepEqual(first, second);
});
```

Add tests for empty input, unusable input, zero length, the maximum output length, and an output request above the maximum.

## Release requirements

Before publishing a binding:

1. Build artifacts for every declared platform.
2. Test installation in a clean environment.
3. Verify debug and release builds call the same core API.
4. Pin compatible `khaos_core` versions.
5. Publish generated type declarations or stubs.
6. Document supported runtimes and architectures.
7. Include an experimental and unaudited warning.
8. Run a smoke test against the packaged artifact, not only the workspace source.
9. Define the policy for unsupported platforms.
10. Update the API reference and this compatibility table.

## Pull request checklist

A binding pull request should include:

- The adapter crate or FFI module.
- The high-level package when the ecosystem needs one.
- Conversion tests.
- Error-mapping tests.
- A packaged-artifact smoke test.
- Installation documentation.
- A usage guide in the target language.
- CI jobs for declared platforms.
- No duplicated entropy pipeline code.
